# 系统架构

## 总览

仓库分四层：**入口脚本层**（`scripts/*.py`）→ **领域包层**（`scripts/instascene/`）→ **数据资产层**（本地场景数据、prompts、configs、assets 本体）→ **输出层**（`outputs/run_*`）。领域包按职责分为 `scene`（数据加载）、`vlm`（标注 pipeline）、`manifest`（大库抽样清单）、`stats`（统计）。

```
┌─────────────────────────── 入口脚本层 ───────────────────────────┐
│ vlm_gen_scene_desc.py   sample_scenes.py   batch_manifest_stats.py │
│ ask_vlm_image_audit.py  visualize_sam_masks.py                    │
└──────────┬──────────────────────┬──────────────────┬─────────────┘
           ▼                      ▼                  ▼
┌───────── instascene 包 ──────────────────────────────────────────┐
│  vlm/        pipeline  config  selector  preparer  client        │
│  scene/      loaders(scene/masks/sam2)  pairing  discovery  models│
│  manifest/   sample  sample_registry  roots  io  models          │
│  stats/      scene_views                                          │
│  types.py    (Literal 类型 + 支持的图片后缀)                        │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌───────── 数据 / 资产 ─────────┐   ┌───────── 输出 ───────────────┐
│ 3dovs/ lerf/ zipnerf/ (本地)  │   │ outputs/run_*/<ds>/<scene>/  │

│ prompts/*.prompt              │   │   errors.log                 │

│ assets/ (物理本体 ontology)    │   └──────────────────────────────┘
└───────────────────────────────┘
```

## 主干执行链（标注 pipeline）

`vlm_gen_scene_desc.py` → `process_scene()`（`instascene/vlm/pipeline.py:150`），单场景内部流程：

```
CLI 参数
  └▶ PipelineConfig（5 个子配置：scene_input / object_filter / view_render / vlm / run）
       │
       ▼
load_scene()                      scene/loaders/scene.py:90
  ├─ id_map_source 分派:
  │    npy  → id_maps/*.npy + 按同名 stem 配对图像
  │    png  → sam/<mask_subdir>/*.png + 按 stem 配对
  │    sam2_json → auto_masks.json RLE 解码 + 按排序索引配对
  ├─ mask 尺寸不符 → 最近邻 resize 到图像大小
  └─ 汇总: SceneData{views, object_ids, object_to_views}
       │

  ├─ 多图打进单条 user message（data:image/jpeg;base64 URL）

### 并发与容错模型

- 物体级并发：每个 object_id 一个 asyncio task，`VLMClient` 内 `Semaphore(max_concurrent)` 限流。
- 请求级重试：`max_retries` 次、`retry_backoff_seconds * 2^attempt` 退避。
- 物体级隔离：单物体最终失败仅追加 `errors.log`，不影响其它物体；场景结果始终写出。
- 断点续传：输出 JSON 已存在时，其中已有的 object_id 不再处理（`--object-id` 强制重跑指定物体）。

## 辅助链（InsScene-15K 抽样 → 统计）

这条链服务于"从远端大库（infinigen / re10k / scannetpp_v2 三个 processed extract）挑选场景"：

```
sample_scenes.py --dataset {infinigen|re10k|scannetpp_v2}
  └▶ sample_registry.py: 每个数据集绑定 SampleJobConfig
        {default_root(写死共享存储路径), discover 函数, pair_by 策略}
  └▶ discovery/ins_scene_15k.py: 按各自目录约定扫描有效场景
        infinigen:  scene_*/<name>/frames/Image/camera_0 + ObjectSegmentation/camera_0
        re10k:      <scene>/rgb + cam，mask 在 sam2_results/<scene>/auto_masks.json
        scannetpp:  <scene>/images + refined_ins_ids
  └▶ manifest/sample.py: 随机抽 N 个（--seed 可复现）→ 写 manifest JSON
        {dataset_root, pair_by, scenes:[{partition, scene_name, scene_root, image_dir,
                                          id_map_dir | id_map_json}], ...}

batch_manifest_stats.py --manifest xxx.json
  └▶ manifest/io.py: 加载校验 manifest，相对路径基于 dataset_root 解析
  └▶ stats/scene_views.py: 逐场景配对图像与 mask（pair_by: stem|infinigen），
        统计 n_views / n_objects（distinct id ≥ 0），单场景异常记入 error 不中断
  └▶ 写聚合统计 JSON（totals: n_scenes/n_ok/n_errors/sum_views）
```

两条链的衔接点：manifest 描述的场景路径格式与 `load_scene` 支持的三种 id map 来源一致，统计链在正式跑标注前用于评估数据规模与可用性。

## 关键设计决策

| 决策 | 说明 |
|---|---|
| 图像配对策略抽象为 `PairingStrategy` | `stem`（同名配对，3dovs/ScanNet++）与 `infinigen`（`Image_*` ↔ `ObjectSegmentation_*` 前缀剥离）两种，sam2_json 则按排序索引对齐 |
| 拼图规格外置为 JSON spec | `configs/view_compose_*.json` 控制发给 VLM 的面板组合与布局，实验不同"提示图"形式无需改代码 |
| prompt 外置为 `.prompt` 文件 | `prompts/` 下多个版本（simple/concise/verbose/v2）做 prompt 实验；模板即 Python format 字符串 |
| 标注 schema 外置为本体 JSON | `assets/` 定义 `instance_physics_perception_v1` 各字段枚举与规则，prompt 中的枚举值与之对应 |
| OpenAI 兼容协议 | 只依赖 `base_url + api_key + model_name`，可切 GPT / Qwen / 任意代理（实际用过 yunwu.ai 代理） |
| 输出按 run 隔离 | `outputs/run_<ts>/` 保留每次实验完整输入输出（含 debug_inputs），便于横向对比模型/prompt/拼图方案 |
