# 重要功能模块

按重要性排序。路径均相对 `scripts/instascene/`（入口脚本除外）。

## 1. vlm/pipeline.py — 主编排（核心）

- `process_scene(config, dataset, scene) -> Path`（:150）：单场景全流程。加载场景 → 确定 pending 物体（断点续传/`--object-id`/`--single-object`）→ 并发处理每个物体（选视角→拼图→调 VLM）→ 合并写出 JSON。
- `_try_parse_json(text)`（:29）：从 VLM 回复里剥 markdown 围栏、正则抓 `{...}`，尽力解析成 dict；失败则原文入库并标 `parse_failed: true`。
- 输出条目结构：`{id, instance_id: "<ds>_<scene>_inst003", n_views, mode, response}`。
- `_dump_debug_batch`（:107）：把实际发送的 prompt 文本、每张图（解码回 jpg）、batch 元信息存进 `debug_inputs/object_XXX/`——排查"模型看到了什么"的第一手材料。
- 已知小瑕疵：多 batch 时 debug dump 固定传 `batch_index=0`（:206），多个 batch 会互相覆盖；当前 preparer 只产单 batch，无实际影响。

## 2. vlm/config.py — 配置中枢

- `PipelineConfig` 聚合 5 个 dataclass：`SceneInputConfig`（数据在哪、mask 什么格式）、`ObjectFilterConfig`（视角过滤三阈值）、`ViewRenderConfig`（max_views、拼图 spec）、`VlmConfig`（API/模型/prompt/并发/重试）、`RunControlConfig`（输出目录、单物体模式、debug 开关）。
- `DEFAULT_VIEW_COMPOSE_SPEC`（:21）：默认三面板横排 origin | mask_bw | highlight。
- `resolve_vlm_prompt_template` / `resolve_view_compose_fields`：文件优先于内联字符串的解析规则。
- `scene_output_dir()`（:147）：相对 `output_dir` 会拼在 `data_root` 下——这就是为什么 `outputs/` 出现在仓库根。

## 3. scene/loaders/scene.py — 场景加载统一入口

- `load_scene()`（:90）：三种 `id_map_source` 统一产出 `SceneData`。核心后处理：遍历所有视角 mask 的 `np.unique` 建 `object_to_views`（物体 → 出现过的视角列表），负数 ID 丢弃。
- `build_views_from_sam2_json()`（:62）：RE10K 路径；默认 JSON 位置约定 `<scene_root>/../sam2_results/<scene>/auto_masks.json`。
- `_resize_mask_to_image`（:27）：mask 与图像尺寸不符时最近邻缩放。
- 配套：`loaders/masks.py`（npy/png 单文件读取）、`loaders/sam2.py`（RLE→id map：第 k 个 RLE 得 id k+1，0 为背景；帧数与图像数不符时告警取 min）。

## 4. vlm/selector.py — 视角质量筛选

- `select_views_for_object()`（:66）：对物体在每个视角构建 `ViewInfo`（binary mask、bbox、pixel_count、bbox_area_ratio、pixel_ratio），过三阈值，按 `quality_score = 像素占整图比×0.7 + mask占bbox比×0.3` 降序取 top `max_views`（`max_views<=0` 表示不限）。
- 这是控制"喂给 VLM 什么素材"的第一道闸门，标注质量差先查这里的阈值。

## 5. vlm/compose.py + vlm/preparer.py — 拼图 spec 与渲染

- `compose.py`：compose spec 的类型化模型（`ComposeSpec` / `PanelSpec` / `LayoutSpec` / `TitleSpec` / `MaskBwSpec` / `HighlightOutsideDarkSpec`）与 `parse_compose_spec()`——所有校验、默认值、数值 clamp、grid 行列解算都在解析期一次完成，渲染期只消费类型化字段。新增面板变体需登记 `KNOWN_PANEL_VARIANTS`。
- `preparer.py`：`prepare_image_batches()` 按 spec 把每个视角渲成一张多面板拼图，全部视角合成**一个** `ImageBatch(mode="compose")`。
- 面板变体（`_render_variant`）：`origin` 原图 / `mask_bw` 黑白掩码 / `highlight_outside_dark` 目标外压暗 / `overlay` 画 bbox·轮廓·半透明填充 / `crop` 白底扣图（带 padding）。
- 布局：horizontal / vertical / grid（可指定 rows/cols），pad 居中对齐，可加标题栏。
- spec 示例见 `configs/view_compose_h2.json`（双面板）与 `h3.json`（2×2 四面板）。

## 6. vlm/client.py — VLM API 封装

- `VLMClient.infer()`：AsyncOpenAI，多图 base64 data-URL 塞进单条 user message，Semaphore 并发限流 + 指数退避重试。
- `audit_images()`：同步版探针，供 `ask_vlm_image_audit.py` 用——让模型自报"看到几张图、各是什么"，验证代理/模型是否丢图。
- `extract_text()`：兼容 content 为字符串或分段列表两种返回格式。
- 图像读取/JPEG-base64 编码统一在 `instascene/imaging.py`（preparer 与 client 共用同一份实现）。

## 7. manifest/* — InsScene-15K 抽样清单

- `sample_registry.py`：`SAMPLE_JOB_CONFIGS` 注册三个数据集（infinigen/re10k/scannetpp_v2），各绑定默认根路径、discover 函数、pair_by 策略。**新增数据集在这里加一项即可**。
- `sample.py`：通用抽样 CLI 骨架（`run_sample_job`）：discover → 随机抽 N（--seed 可复现，--shuffle，--strict）→ 写 manifest JSON。
- `io.py`：manifest 加载/校验/路径解析（相对路径基于 `dataset_root`）。
- `roots.py`：共享存储上 InsScene-15K 的写死路径。
- `models.py`：`ScenePathsManifestEntry`（原始字符串路径）与 `ResolvedScenePaths`（绝对 Path，含 `scene_key` 属性）。

## 8. scene/pairing.py + scene/discovery/ — 配对与发现

- `pairing.py`：`pair_image_and_masks(strategy=)` —— `stem` 同名配对；`infinigen` 剥 `Image_` / `ObjectSegmentation_` 前缀后配对。
- `discovery/local.py`：本地数据根的 dataset/scene 发现（有 `images/`+`sam/` 才算场景），供 `--dataset all` 用。
- `discovery/ins_scene_15k.py`：三个远端 extract 的目录约定扫描（详见架构文档）。

## 9. stats/scene_views.py — 场景统计

- `summarize_manifest_scene()`（:60）：对 manifest 单场景做与 `load_scene` 一致的配对逻辑，数 `n_views` 与 distinct `n_objects`（id≥0）；异常捕获进 `error` 字段不中断批量。供 `batch_manifest_stats.py` 调用。

## 10. 入口脚本（scripts/）

| 脚本 | 作用 |
|---|---|
| `vlm_gen_scene_desc.py` | 主链 CLI：全部参数 → `PipelineConfig` → 遍历 dataset/scene 调 `process_scene` |
| `sample_scenes.py` | 辅链 CLI：`--dataset` 先行解析选中 SampleJobConfig，剩余参数交给通用抽样器 |
| `batch_manifest_stats.py` | manifest 批量统计，`--pair-by auto` 时优先用 manifest 内记录的 `pair_by` |
| `ask_vlm_image_audit.py` | VLM 多图可见性探针（支持 `--dry-run` 只编码不发请求） |
| `visualize_sam_masks.py` | 独立小工具：id mask 确定性上色可视化（不依赖 instascene 包） |

## 11. 数据资产（非代码但同等重要）

- `assets/`：`instance_physics_perception_v1` 本体——7 个字段（scene_role / geometry_form / attachment_relation / appearance_material_topk / 三个 physical_priors bin）的枚举定义与标注规则；`instance_record.template.json` 是单实例标注记录模板；`ontology_manifest.json` 声明当前 schema 激活字段。
- `prompts/`：物理感知 prompt 的多个版本（simple / concise / verbose / v2），要求模型直接输出符合本体枚举的 JSON。
- `configs/`：view compose spec（h2 双面板 / h3 四面板网格）。
- 本地场景数据：`3dovs/{bed,bench,room}`、`lerf/{figurines,teatime}`、`zipnerf/{alameda,nyc}`，每场景 `images/ + sam/mask/ + id_maps/ + sparse/`（COLMAP）。
